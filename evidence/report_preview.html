3. Arsitektur Jaringan Kontainer & Penjelasan Desain

Sistem dirancang mengacu pada 8 pedoman teknis Modul Praktikum Komputasi Awan:

  • Multi-Stage Dockerfile: Memisahkan stage base, stage test (quality gate tanpa ketergantungan host), dan stage runner (hanya memuat file produksi serta dijalankan dengan user non-root ruangkita).
  • Isolasi Jaringan Internal (internal: true): Service database PostgreSQL berada di jaringan ruangkita_backend_net yang diisolasi penuh dari jaringan eksternal. Hanya service app yang terhubung ke jaringan publik ruangkita_public_net untuk menerima traffic HTTP port 8000.
  • Persistensi Data & Healthcheck Dependensi: Volume ruangkita_postgres_data menjamin data reservasi tidak terhapus saat redeploy. Service app menggunakan depends_on dengan condition: service_healthy agar web baru menyala setelah database siap menerima query.

4. Alur Otomasi Pipeline Jenkins (6 Stages Berurutan)

Pipeline berjalan otomatis setiap kali ada event merge ke branch main yang dipicu oleh GitHub Webhook via Ngrok:

Checkout ──> Test (Quality Gate) ──> Build Image ──> Push Image ──> Deploy (Compose) ──> Smoke Test (Git SCM) (docker build test) (Tag BUILD & latest) (Docker Hub PAT) (Auto-Rollback Prep) (curl /health == 200)

6. Tantangan Khusus K10: Auto-Rollback ke Image Sebelumnya

Pada studi kasus RuangKita (K10), tantangan DevOps wajib adalah Rollback otomatis ke image sebelumnya:

  • Pada stage Deploy, script mencatat tag image yang sedang berjalan ke dalam file .previous_deployed_tag.
  • Aplikasi versi baru kemudian di-deploy menggunakan image tag terbaru.
  • Pada stage Smoke Test, endpoint GET /health diuji. Jika respons bukan 200 (misalnya simulasi kegagalan server), pipeline gagal dan blok post { failure { ... } } secara otomatis men-deploy ulang tag image sebelumnya yang stabil.
